Programa educativo: Tecnología de la Información e Innovación

## 1. PRESENTACIÓN

La asignatura de Desarrollo de Aplicaciones Nativas introduce al estudiante en el análisis, diseño, programación, prueba y publicación de aplicaciones móviles construidas específicamente para un sistema operativo. A diferencia de una aplicación web, una aplicación nativa utiliza las herramientas, lenguajes, componentes y servicios propios de una plataforma móvil.

El curso integra fundamentos de programación, diseño de interfaces, navegación entre pantallas, almacenamiento local, consumo de servicios, uso responsable de permisos, pruebas y seguridad. La plataforma concreta, el lenguaje y el entorno de desarrollo deberán definirse de acuerdo con el equipamiento institucional. Se puede trabajar con Android, iOS o una comparación introductoria entre ambas plataformas.

La arquitectura debe considerarse desde las primeras etapas, ya que una estructura adecuada favorece aplicaciones robustas, probables de probar y mantenibles. [web:27] Asimismo, la seguridad móvil se abordará tomando como referencia controles de almacenamiento, criptografía, autenticación, red, plataforma, código, resiliencia y privacidad propuestos por OWASP MASVS. [web:29][web:34]

## 2. PROPÓSITO GENERAL

Desarrollar una aplicación móvil nativa funcional, segura y centrada en las necesidades del usuario, aplicando principios de programación, diseño de interfaces, arquitectura, persistencia de datos, consumo de servicios y pruebas.

## 3. COMPETENCIA DE LA ASIGNATURA

Diseñar, programar y evaluar aplicaciones móviles nativas mediante herramientas de desarrollo de la plataforma seleccionada, integrando interfaces, navegación, datos, servicios y prácticas básicas de seguridad y calidad.

## 4. RESULTADOS DE APRENDIZAJE

Al finalizar la asignatura, el estudiante será capaz de:

- Diferenciar aplicaciones web, híbridas, multiplataforma y nativas.
- Identificar las características de una plataforma móvil y su ciclo de vida.
- Configurar un entorno de desarrollo y crear un proyecto nativo.
- Construir interfaces utilizando componentes propios de la plataforma.
- Implementar navegación entre pantallas.
- Aplicar eventos, validación y manejo de estados.
- Utilizar componentes reutilizables.
- Almacenar y consultar información localmente.
- Consumir un servicio web mediante una API.
- Gestionar permisos de manera justificada.
- Aplicar controles básicos de seguridad y privacidad.
- Realizar pruebas funcionales, de interfaz y de dispositivos.
- Documentar, generar y presentar una versión instalable de la aplicación.

}

# UNIDAD IV. DATOS LOCALES Y CONSUMO DE SERVICIOS

## Objetivo:
Almacenar información localmente y consumir datos provenientes de servicios web.

## Contenidos:
- Modelos y estructuras de datos.
- Preferencias simples.
- Archivos locales.
- Bases de datos móviles.
- Operaciones de alta, consulta, actualización y eliminación.
- Serialización y deserialización.
- Concepto de API y endpoint.
- Solicitudes HTTP.
- JSON.
- Estados de respuesta.
- Operaciones asíncronas.
- Indicadores de carga y manejo de errores de red.
- Separación entre interfaz, lógica y datos.

## Flujo sugerido para consultar una API:
1. Mostrar indicador de carga.
2. Realizar la solicitud.
3. Verificar la respuesta.
4. Convertir los datos al modelo de la aplicación.
5. Mostrar el resultado.
6. Informar errores y ofrecer reintento.

## Ejemplo de estructura JSON:

{
  "id": 1,
  "nombre": "Taller de innovación",
  "cupo": 25,
  "disponible": true
}

## Buenas prácticas:
- No almacenar contraseñas en texto plano.
- No incluir claves secretas directamente en el código publicado.
- Validar datos recibidos de servicios externos.
- Evitar bloquear la interfaz durante operaciones de red.
- Informar al usuario cuando no exista conexión.

## Producto:
Aplicación que almacene registros localmente y consulte información de un servicio web o conjunto de datos simulado.

# 11. GLOSARIO BÁSICO

Aplicación nativa: software desarrollado específicamente para una plataforma y sus herramientas.

SDK: conjunto de herramientas, bibliotecas y recursos para desarrollar aplicaciones.

API: interfaz que permite la comunicación entre componentes o aplicaciones.

Emulador: programa que simula un dispositivo o sistema.

Simulador: entorno que reproduce parte del comportamiento de una plataforma.

Actividad o pantalla: componente visual y funcional que presenta una parte de la aplicación, según la plataforma.

Interfaz: conjunto de elementos mediante los cuales el usuario interactúa con la aplicación.

Estado: condición actual de una pantalla o proceso, como cargando, vacío, éxito o error.

Persistencia: conservación de datos para utilizarlos posteriormente.

JSON: formato de texto utilizado para intercambiar datos estructurados.

Endpoint: dirección específica de un servicio web.

Permiso: autorización solicitada por una aplicación para acceder a una capacidad o recurso.

Autenticación: proceso de verificar la identidad de una persona o sistema.

Autorización: proceso de determinar qué acciones puede realizar una identidad.

# 12. RECOMENDACIONES PARA EL ESTUDIANTE

- Definir primero el problema y no comenzar por las pantallas.
- Mantener un alcance pequeño y realizable.
- Probar cada componente antes de integrarlo.
- Utilizar control de versiones desde el inicio.
- No copiar claves, contraseñas ni datos sensibles en el repositorio.
- Solicitar únicamente permisos necesarios.
- Revisar los mensajes de error del entorno.
- Probar con datos válidos, inválidos, vacíos y extremos.
- Verificar la aplicación en más de un tamaño de pantalla.
- Documentar decisiones técnicas y limitaciones.
